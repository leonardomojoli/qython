# Contribuições

O Qython é software livre ([AGPL-3.0-only](LICENSE)) para médicos e instituições de saúde no Brasil. Ele é
escrito e mantido por uma única pessoa e **não aceita pull requests nem contribuições de código**: o
mantenedor decide sozinho o que entra. Isso não muda a licença: você pode usar, estudar, modificar e
redistribuir o código nos termos da AGPL, inclusive num fork seu.

## O que ajuda

- **Problemas e ideias** vão para as [issues](https://github.com/leonardomojoli/qython/issues/new/choose).
  Procure antes se já existe uma. Descreva o comportamento esperado e como reproduzir; evite colar código
  pronto como solução.
- **Relatos de uso real** dizem mais sobre o que falta do que qualquer lista: conte o que tentou e o que
  aconteceu.
- **Conteúdo clínico** (doses, interações, condutas, CID-10): ao apontar um erro, cite a fonte (bula da
  ANVISA, diretriz do Ministério da Saúde ou de sociedade brasileira, artigo revisado por pares).
- **Dúvida de uso**: veja [`docs/SETUP.md`](docs/SETUP.md); se não resolver, abra uma issue.
- **Vulnerabilidade de segurança**: não abra issue pública. Veja [`SECURITY.md`](SECURITY.md).
- **Nunca coloque dados de pacientes** (nome, CPF, exames, prints do app com dados reais) em issue ou log.
  Tudo aqui é público. Se um log tiver dados reais, apague antes de colar.

## E os pull requests?

Pull requests de quem não é o mantenedor são fechados automaticamente, com uma mensagem apontando para este
arquivo. Não é nada pessoal: é a regra do projeto. O que você achou, conte numa issue.

## Convivência

Seja respeitoso. Discuta o código e as ideias, não as pessoas.
